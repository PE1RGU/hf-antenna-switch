## 2. Box start-up order against the SAFE loop

| Order | Trace | Loop current at end |
|---|---|---|
| Rule 3 of verify_logic.py (check KILL = 0, then MCU_EN_N = 0) | LATCH_CLR: READY 0, loop 0, KILL 1; waits for KILL = 0: READY is 0, so the loop cannot close: **deadlock** | 0 |
| D-62 order (LATCH_CLR, MCU_EN_N = 0, then wait for KILL = 0) | LATCH_CLR: READY 0, loop 0, KILL 1; MCU_EN_N=0: READY 1, loop 1, KILL 0; wait KILL=0: READY 1, loop 1, KILL 0 | 1 |

| Check | Result |
|---|---|
| Old rule 3 deadlocks under D-62 (expected: shows the conflict) | pass |
| D-62 start-up order closes the loop | pass |

**Finding F11 (firmware).** Rules 3 and 5 of verify_logic.py (section 10) wait for KILL = 0 before MCU_EN_N = 0. With the SAFE loop (D-62), KILL goes to 0 only after MCU_EN_N = 0, so these rules deadlock. New rule: LATCH_CLR, then MCU_EN_N = 0, then wait for KILL = 0 (timeout: report 'SAFE loop open'). On KILL = 1 the relays are already off (the expanders are held in reset by RLY_EN = 0). After KILL returns to 0, the firmware must set up the expanders again (F1 order) before any switching. F5 is reworded in the same way: the relays do not return in their last state, they return off.

## 5. TX handshake for R2 and R3, timed (D-63)

Model, 1 ms steps. Link message 4 ms. Box: on request it checks the state, sets K0, waits 12 ms, reads back, sends the permit. K0 contact: TX 12 ms after the command (operate plus bounce, max); back to RX after the release time (0 ms used as the worst case, because RT1 gives no minimum; 6 ms max). Radio: RF starts when keyed and not inhibited; RF stops t_inh after the inhibit and t_tail after the key opens (both to measure). Hazard X: RF present while the K0 contact is not on the TX row.

| Case | Hazard X (ms with RF off the TX row) | Reading |
|---|---|---|
| N1 normal TX, radio tail 5 ms | 0 | handshake keeps RF on the TX row |
| N2 normal TX, radio tail 50 ms | 0 | the shack waits for TX sense inactive, so a long tail is covered |
| E1 SAFE stop at 0.5 s during TX, radio stops 5 ms after the inhibit | 5 | K0 of R2/R3 drops at once (U903 in reset); RF tail breaks the K0 contact |
| E2 SAFE stop at 0.5 s, radio stops 0 ms after the inhibit | 0 | no hazard only if the radio stops at once |
| E3 shack MCU hangs at 0.5 s with permit set | 0 | box keeps K0: no hazard while the box state does not change |
| E4 TX sense opto failed (reads no TX), radio stops 20 ms after the inhibit | 15 | 'end' goes out at once; K0 releases under RF |
| E5 as E4, shack waits at least 100 ms after the inhibit | 0 | the minimum wait covers a failed TX sense |

| Check | Result |
|---|---|
| Normal handshake: no RF off the TX row, for short and long RF tails | pass |
| Shack MCU hang: the box keeps K0, the shack fault latch inhibits after the watchdog time-out | pass |
| SAFE stop during TX: hazard X depends on the radio inhibit response (expected: shows the weakness, accepted D-76) | pass |
| Failed TX sense: hazard without a minimum wait, none with it (F14) | pass |

**Finding F12 (design).** On a SAFE stop, the box drops RLY_EN at once. U903 goes into reset, so K0 of R2 and R3 releases within 0 to 6 ms, and all row relays open. At the same moment the shack inhibits the radio. A radio that needs a few ms to stop RF after the inhibit then sends RF across an opening K0 and row contacts. R1 is different: its K0 follows the FT-710 TX GND through the PTT loop, which stays closed until the radio ends TX. Row relays opening under RF on an emergency stop is inherent to any stop. The K0 of R2 and R3 could be held for about 50 ms after RLY_EN drops, so the radio is off before K0 moves. This is a decision for later (two options).

**Finding F13 (firmware).** The box must not change K0 or any relay of a radio while its permit is out. On a link time-out it must not release K0; it opens SAFE (MCU_EN_N = 1) instead, which inhibits every radio in hardware at the shack (and then F12 applies).

**Finding F14 (firmware).** An ageing or failed TX sense opto reads 'no TX': this failure is not fail-safe. (The LED ageing of the PhotoMOS parts is fail-safe: a weak LED keeps the form B contact closed, so the radio stays inhibited, and keeps the form A keying contact open.) Rule: after the inhibit, the shack waits for TX sense inactive and at least a minimum time (proposed 100 ms, longer than the measured inhibit response, M-12) before it sends 'end'. A plausibility check flags a port whose TX sense stays inactive while the radio is keyed.

## 6. Firmware rules added by this verification

1. Box start-up: LATCH_CLR, then MCU_EN_N = 0, then wait for KILL = 0 with a time-out; then set up the expanders (F1), then switch (F11). Replaces rule 3 of verify_logic.py.
2. Box on KILL = 1: relays are off in hardware; after KILL = 0, set up the expanders again before any switching (F11). Replaces rule 5 (F5).
3. Box: no change to K0 or to the rows of a radio while its permit is out; on a link time-out, open SAFE, do not release K0 (F13).
4. Shack: at TX end, first inhibit (permit 0, key 0), then wait for TX sense inactive and at least 100 ms (F14), then send 'end' to the box (section 5).
5. Shack: flag a port as faulty when TX sense stays inactive while the port is keyed or the radio should transmit (F14).
6. Shack: kick its own watchdog only from the main loop; a hang then drops all permits (E3).

## Result

All checks pass. Findings F11 to F14: firmware rule changes (F11, F13, F14) and one accepted design point (F12, D-76).
