Controller Card

Slot 0. An ESP32-S3 holds the routing table and talks to every card over I2C, to the host over USB, and to the shack over Wi-Fi. Around it sits a safety chain built so that the firmware can only ever permit relays to be energised: the external watchdog, the supply supervisor and the gate that produces /RLY_EN are hardware. Parent: Shack Relay Matrix · siblings: Radio Port Card, Antenna Port Card.

Blocks

BlockFunction and choice
ESP32-S3-WROOM-1UThe -1U variant has a U.FL socket instead of a PCB antenna, so the Wi-Fi antenna goes through a rear bulkhead SMA and sits outside the steel box. Native USB gives the host a CDC serial port with no bridge chip. Two I2C controllers: #1 is the backplane master, #2 drives the front panel, so a wedged card cannot freeze the display.
USB-CHost link only. ESD array on the data pair. The 5 V from the host is not used to power anything; the card runs from the backplane so the switch works with the PC off.
Card power+5 V from the Power module through a 1 A 3V3 LDO on this card. The ESP32 draws 500 mA bursts on Wi-Fi TX; keeping that off the shared backplane 3V3 keeps the card-side expanders and comparators quiet.
External watchdogTPS3823 class, 1.6 s window, kicked from a GPIO in the main loop. The ESP32's internal watchdogs only reset the chip; this one also drops WDT_OK, so a hung MCU takes the relays to safe state before it reboots.
Supply supervisorWatches +3V3 and +12V RLY. Under-voltage on either releases PWR_OK. Relays that lose coil voltage mid-transmission are worse than relays that were never closed.
Safety gateSmall logic: /RLY_EN is asserted only while WDT_OK, PWR_OK and MCU_EN are all true and the fault latch is clear. Any of them dropping sets the latch. The MCU can clear the latch only after the ACK button, and only if the inputs are healthy again. Open-drain onto the backplane so a second controller or a panel kill switch could pull it too.
I2C bus bufferPCA9517 between the MCU and the backplane: strong pull-ups on the card side, isolation from a shorted card, and a TCA9548 mux footprint for a second backplane later.
Input bufferSchmitt buffers with pull-ups on PTT[1..4] and /INT. The MCU reads PTT for hot-switch lockout and the display; it never drives those lines.
Front panelRibbon to the panel: 128×64 OLED on I2C#2, encoder with push for pick-and-confirm, MODE and ACK buttons, fault LED. Enough to run the shack with the PC off.
Debug headerUART0, BOOT and RESET on the card edge. Not reachable from the panel.

What the firmware owns

FunctionBehaviour
DiscoveryAt boot: scan slots, read each card's EEPROM (type, name, RX-only, bias-T, TX-capable, TX delay). Build the routing table from what is actually plugged in.
RoutingPer radio slot: TX line and RX line. Enforce one radio per line, RX-only lines only on RX paths, break-before-make, settle delay, no moves while that slot's PTT or RF_DET is active.
Host protocolASCII over USB CDC, same protocol over TCP/WebSocket on Wi-Fi. Commands like SET R1 TX A1 RX A2, STATE, FAULT ACK. Host-side band data from CAT can drive per-band presets.
Web UIMatrix view, tap to route, fault log. mDNS so it is relay-matrix.local.
FaultsRF on an idle or RX-only line, PTT while a move is in progress, expander not answering, EEPROM/DIP mismatch. Log to flash with timestamp (NTP when Wi-Fi is up).
PresetsNamed routes stored in NVS, selectable from encoder, host or web.

Boot and fault sequence

  1. Power up: /RLY_EN released by default (latch set on power-on). Every antenna port grounded, every matrix relay open.
  2. MCU boots, scans cards, loads last state, starts kicking the watchdog, raises MCU_EN.
  3. Firmware clears the latch → /RLY_EN asserted → routes applied in order, RX rows before TX rows.
  4. On any fault: latch sets, /RLY_EN released within microseconds, K0 relays on the radio cards keep following PTT. Display shows the cause. ACK on the panel or host lets the MCU clear the latch.

Open items

  1. Wi-Fi radiated and conducted noise into the HF receive chain. Mitigations drawn in: antenna outside the box, LDO on the card, module far from the RF bus board. Verify with the Airspy before committing the enclosure layout. Fallback is a Wi-Fi-off mode.
  2. Whether TX_ANY (diode-OR of PTT) should be driven onto a spare backplane line by this card or by the Power module; the Radio Port RX variant would prefer a clean single line to read.
  3. Panel kill switch: a physical switch in series with /RLY_EN on the front panel, or trust the ACK-gated latch.
  4. ESP32-S3 I2C at 400 kHz across the full backplane with 10 expanders and 10 EEPROMs: check bus capacitance; the PCA9517 helps but the backplane pull-ups need sizing.
